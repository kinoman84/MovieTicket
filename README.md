# КиноБилет

Учебная система продажи билетов в кино. Репозиторий описывает её текущее
состояние и предназначен для предварительного знакомства перед интервью.

## Структура репозитория

- [Единый REST API-контракт](api/openapi.yaml) — методы КиноБилета для работы с
  каталогом, заказами, оплатой и callback платёжного провайдера.
- [Модель данных](db/data-model.dbml) — DBML-схема локальной БД с таблицами,
  связями и ограничениями.
- [Логика домена cinema](api/cinema/) — описание обработки запросов на просмотр
  кинотеатров, фильмов, сеансов и мест, а также создание и получение заказа.
- [Логика домена payment](api/payment/) — инициация оплаты, обработка callback и
  PlantUML-диаграмма платёжного потока.
- [Контракт внешнего платёжного провайдера](external-systems/payment-provider/openapi.yaml)
  — REST API, через который КиноБилет создаёт платёжную сессию.
- [Архитектурная LikeC4-диаграмма](architecture/kinobilet-components.c4) —
  основные компоненты и связи между ними.
- [Ключевые сценарии](docs/scenarios.md) — основные пользовательские потоки
  выбора, оформления и оплаты билетов.

## Границы текущей версии

Покупатель выбирает сеанс и место, оформляет заказ, переходит по платёжной
ссылке и получает подтверждение оплаты. Каталог кинотеатров, залов, мест, фильмов
и сеансов хранится в локальной БД КиноБилета. Единственная внешняя интеграция —
абстрактный платёжный провайдер.

При запуске оплаты КиноБилет вызывает REST API провайдера и сохраняет полученную
платёжную ссылку. После оплаты провайдер вызывает endpoint КиноБилета; по этому
callback система меняет статус платежа, заказа и билетов.

## Роли

- **Покупатель** выбирает сеанс и места, оформляет и оплачивает заказ.
- **Платёжный провайдер** создаёт платёжную сессию и сообщает её итоговый статус.
