# Создание заказа

## Описание

Метод вызывается покупателем для резервирования выбранных мест одного сеанса. Он
создаёт заказ и билеты только если все выбранные места принадлежат сеансу и ещё
не заняты активными билетами.

## URL

`POST /v1/orders`

## Логика обработки запроса

1. Найти запись в таблице [screenings](../../db/data-model.dbml), для которой
   `screenings.id` равен
   идентификатору сеанса из запроса.
   * Если сеанс не найден, не создавать заказ и вернуть `404 Not Found`.
2. Получить записи из таблицы [seats](../../db/data-model.dbml), идентификаторы которых переданы в запросе,
   и проверить, что все они принадлежат залу найденного сеанса.
   * Если хотя бы одно место не найдено или относится к другому залу, не изменять
     данные и вернуть `422 Unprocessable Content`.
3. В одной транзакции проверить доступность выбранных мест. Для каждого места не
   должна существовать запись в [tickets](../../db/data-model.dbml), для которой
   `tickets.screening_id` равен идентификатору сеанса, `tickets.seat_id` равен
   идентификатору места и `tickets.status` имеет значение `held` или `paid`.
   * Если хотя бы одно место недоступно или уникальное ограничение
     `uq_tickets_screening_seat` не позволяет создать билет, откатить транзакцию
     без создания заказа и билетов и вернуть `409 Conflict`.
4. Создать запись в [orders](../../db/data-model.dbml) для найденного сеанса со статусом
   `pending_payment`, email покупателя из запроса и итоговой суммой, равной сумме
   цен создаваемых билетов.
5. Создать для каждого выбранного места запись в [tickets](../../db/data-model.dbml) со статусом `held` и
   ценой, равной `screenings.base_price`. Связать каждый билет с созданным
   заказом, сеансом и местом.
6. Зафиксировать транзакцию и вернуть созданный заказ в соответствии с
   [контрактом](../openapi.yaml).
